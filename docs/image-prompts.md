## How to use this

Every prompt is self-contained — copy the whole block, no need to add a style
line. They share a house look on purpose: charred oak, real flame, warm rim
light, near-black background. That consistency is what makes a menu feel like
one shop rather than a stock-photo bin.

**Sizes**

| What | Ratio | Pixels |
|---|---|---|
| Products | 1:1 | 1200 × 1200 |
| Deals | 16:9 | 1600 × 900 |
| Sections | 3:2 | 1500 × 1000 |

**Negative prompt — use on all of them**

```
blurry, plastic-looking cheese, cartoon, illustration, 3d render, watermark, text, letters, logos, hands, fingers, cutlery, white background, flat lighting, oversaturated, uncooked dough, burnt black, floating ingredients, duplicate crusts
```

**Before you send them to me**

1. Name each file exactly as the `filename` line says — that is how they get
   matched to the right item.
2. Run them through [squoosh.app](https://squoosh.app) first. Raw output is
   often 4–5 MB; target **under 300 KB** each. Format does not matter much —
   the site converts to AVIF automatically — but the source size does, because
   a 5 MB source is slow to convert the first time.
3. Send them over and I will drop them in, or set them yourself in the back
   office: **Menu → the item → Edit → Photo**.

**One honest warning.** Generated food photography sells a pizza that does not
exist. If a customer orders the Mega Ball and it looks nothing like the picture,
that is a complaint and, for a real shop, arguably a misleading advert. The 52
photographs already on the site have the same issue. Worth a conversation with
the owner about getting a phone and half an hour on a quiet afternoon — real
photographs of the actual food outperform generated ones for a local takeaway,
because people recognise their own dinner.
